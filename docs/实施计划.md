# Paseo Sync 原生插件实施计划

> 执行方式：使用 superpowers-executing-plans，逐项执行并以 TDD 验证。用户已确认方案并授权实现、创建个人公开仓库。

**目标：** 在每台 Paseo daemon 提供原生界面，完成私有 Git 配置的检查、发布、拉取应用和恢复。
**架构：** 原生 React Native 界面、Zod RPC、服务端共享同步核心、官方 Paseo CLI 和 Git 适配器；独立公开代码仓库，个人配置仍留在私有仓库。
**技术栈：** Paseo SDK 0.11.4、TypeScript、Node >=22.18、React Native、Node test。
**规格：** 已确认的聊天方案；首版手动同步、固定版本、设置白名单、不自更新、不更换插件来源、不覆盖 Git 冲突。

## 全局约束

- 插件目录与个人配置仓库分离；公开仓库不复制 profile.json、真实 settings、身份与认证信息或私有 Git 历史。
- 当前 daemon 为唯一执行目标；同步插件自身不纳入导出或应用，不自动开启插件全局开关。
- SDK 未公开完整插件管理接口，使用官方 CLI；不卸载重装、不使用私有 RPC。
- Git 凭据由本机 credential helper/SSH 管理；非交互、限时执行，不强推，不自动清理。
- 原始状态摘要确认、主机端锁、备份、设置原始字节比较继续生效。保留备份，不自动清理。

## Review Focus

1. registry 来源不接受显式版本时必须在预览阻止，不能静默装成 latest。
2. 更新失败或中断后保留备份和明确阶段；同一 daemon 的不同 checkout 也不能并发写入。
3. Cafe 原有设置和排除项应保留；设置预览过期或并发写入时拒绝。
4. Git 发布只提交允许的配置文件，不提交个人仓库其他文件，不覆盖远端进展。
5. 同步插件自身、目录安装插件、GUI PATH 与 Windows 命令边界需明确处理。

### Task 1: 固定版本切换和恢复

文件：`server/core/{paseo,sync,profile,export}.mjs`、`tests/{paseo,sync,export}.test.mjs`。
接口：adapter.update(target)；buildPlan/applyPlan/restorePlan/restore 保持现有接口。

- [ ] 写测试：模拟官方重复 ID 拒绝，验证 npm 升级、降级和恢复使用 update；阻止来源切换、registry 不可表示的显式版本、自身操作。
- [ ] 运行 npm test，观察新断言失败。
- [ ] 实现 install/update 分类、明确冲突和恢复支持；保留禁用目标安装保护。
- [ ] npm test 全绿后提交。

### Task 2: Cafe 管理权和 Git 工作流

文件：`server/core/{cafe,repository}.mjs` 及测试。
接口：Cafe preview/apply，保留原字段、CAS 和停止再写；Git prepare/publish，仓库检查、受限文件 diff 摘要、确认后提交推送。

- [ ] 写测试：Cafe 排除项合并、并发修改拒绝、恢复；Git 干净工作区、冲突、发布白名单和过期摘要。
- [ ] 观察失败，最小实现，再运行完整测试并提交。

### Task 3: 原生插件与持久化操作

文件：`shared/{settings,rpc}.ts`、`server/{service,jobs}.mjs`、`index.server.ts`、`client/sync.tsx`、`index.client.tsx`。
接口：配置当前主机 checkout/CLI；RPC 预览返回摘要，执行返回 jobId；job 状态 queued/running/succeeded/failed/interrupted、result/error/phase。

- [ ] 写服务测试：并发锁、任务持久化、重启标为中断、旧预览拒绝、自身排除。
- [ ] 观察失败，实现服务层与原生界面，定时查询正在运行的任务；不做定时后台同步。
- [ ] 类型检查、完整测试、打包内容检查、隔离 daemon 编译和真实 RPC 验证。
- [ ] 文档标明真实 macOS/Windows 与客户端验证边界，提交。
