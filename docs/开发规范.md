# 开发规范

## Paseo 约定

- `paseo-plugin.json` 声明安装 ID 和已验证的宿主版本；`index.client.tsx` 与 `index.server.ts` 注册贡献。
- 其他代码分别放在 client、server、shared。客户端用 React Native 和宿主 UI 组件；Node、文件和子进程操作只放服务端。
- RPC 使用 shared 中的 Zod 契约。长任务返回操作 ID，由客户端查询，不能把任务生命周期绑定到界面。
- host 设置用 `defineSettings` 与 revision 检查。它不能代替其他插件的设置 API；跨插件适配器必须验证版本与字段，保留其他数据。
- 0.11.4 公开 SDK 没有完整插件安装/更新管理门面，生产代码使用官方 CLI，不导入宿主私有模块。
- 服务端核心使用标准 Node 模块，无运行时第三方安装依赖。MJS 模块位于 server 内，已通过实际宿主编译；CLI 引用同一份模块。

## 变更验证

先添加可复现的失败测试，再实现行为。测试应覆盖可观察结果、冲突和恢复，不只断言方法被调用。宿主版本、设置文档版本与安装来源是独立维度；不能用手写的旧格式 fixture 代替当前插件格式验证。

本地开发依赖只用于类型检查和测试。修改 UI 后至少验证目标宿主实际编译；修改进程管理、CLI、设置或版本切换后使用隔离 daemon 验证。所有集成测试都必须显式选择临时 home，不读取个人配置仓库。

更新此插件应先结束同步任务，再由 Paseo 插件管理入口更新。自身更新和批量跨 daemon 控制不属于首版事务。

## 发布

个人配置不能进入本仓库或插件包。发布前检查 Git 暂存列表、历史、打包文件列表、类型检查、单元测试、隔离集成结果和 CI。Git 标签应指向已验证提交；正式更新后核对安装来源和实际 revision。

当前只通过 Git 分发，不自动提交公开市场，不发布 npm 包。若将来上市场，另行准备截图和描述，按官方规则披露软件安装和主机权限。市场 OVERVIEW 不放开发安装命令；README 记录安装与验证边界。
