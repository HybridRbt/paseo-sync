# 接口设计

## 存储与数据边界

公开插件只包含代码，不包含个人清单。个人仓库采用 `profile.json` schemaVersion 1：plugins 保存 id、source、revision、enabled，可选 pluginPath、registry；settings 保存 plugin、document、file；patches 保存 plugin、file。ID 使用小写字母开头的字母、数字、下划线和连字符；版本必须是精确 npm semver 或 Git 40 位 SHA。路径为规范相对路径，禁止越界与符号链接。

设置只允许 Better Paseo presentation；schemaVersion 或未知字段不兼容时拒绝。源码补丁绑定插件版本，包含文件路径、前后 SHA256、精确替换字符串及次数。清单校验通过后才允许写入。

插件自身的 host 设置文档为 `connection`，version 1：checkout 是配置仓库本机绝对路径，repositoryUrl 是首次克隆地址，cliPath 是可选 CLI 绝对路径，daemonHome 是可选 daemon 目录。空目录和路径错误在操作时报告，不猜测远程主机。URL 不允许携带密码或 token；Git 认证走主机既有配置。

任务和备份存放在插件安装目录、配置仓库之外。锁按 daemon home 共用；基线与备份另按 checkout 区分。备份首版保留，不自动清理。原生插件与 CLI 使用同一状态目录规范。

## 仓库识别与客户端语言

`sync.discover` 输入可选 checkout（最大 4096 字符，禁止控制字符）；省略时读取已保存路径。输出 candidates、selected（可为空）、savedInvalid、limited、scanned。候选包含 checkout、repositoryUrl、pushUrl（URL 可为空）、remoteWarning、source（saved/history/search）。唯一且搜索未受限时才自动选择；有效的已保存路径直接选用。失效路径返回提示，不修改设置。此 RPC 不要求 CLI 可运行，不创建任务或写文件；它只读取主机上的目录和 Git 元数据。

识别采用 `profile.json` schemaVersion 1 校验和 Git 根目录检查，排除插件源码仓库及 daemon home 内的路径。扫描预算见 README。历史文件 `connections.json` 在状态根目录中，最多保存 20 个成功使用的路径；识别只读取，后续操作验证上下文后记录。URL 只允许无凭据/查询参数的 HTTPS 或受支持的 git@ SSH 形式，多个 push URL 无法作为单一推送目标展示时返回警告。

界面异步查找携带开始时的 draft；完成时如路径或 URL 已被用户修改，不覆盖输入。切换主机或关闭页面后忽略旧请求。发现路径和 URL 只填草稿，仍通过 revision 校验保存。

中英文文案位于 `client/i18n.mjs`；语言选择只在客户端保存，不能写入 host `connection` 文档。宿主 SDK 0.11.4 没有语言桥接，当前入口只提供手动 en/zh；纯语言解析函数预留 host locale 参数，但没有声称任何未提供的宿主接口已接通。未知宿主语言映射英文，未提供宿主语言时保持本版默认中文。

## RPC

- `sync.start` 输入 kind，可选 approval、backupId；立即返回 id、kind、status。kind 为 prepare、inspect、plan、apply、publishPlan、publish、cafePlan、cafe、backups、restorePlan、restore、verify。
- `sync.job` 输入可选 UUID id，省略返回最新任务；输出 JSON，未有任务时为 null。
- `sync.unlock` 只允许解除已确认原持有进程退出的任务锁；不能删除无法确认归属的执行锁。
- 宿主 SDK 自动提供 `settings.connection.read/write/reset`，设置写入使用宿主 revision 防止并发覆盖。

任务字段：id、kind、status、phase、startedAt，可选 finishedAt、result、error、backupId。status 为 queued、running、succeeded、failed、interrupted。任务阶段使用 checking、preview、git-fetch-and-fast-forward、backup-and-execute、complete。错误经过脱敏，设置内容不会写入公开仓库。

预览包含 approval 与 confirmKind；恢复预览还包含 backupId。approval 将配置路径、daemon home、操作类型与内部状态摘要绑定。服务端每次执行重新读取并验证；内部同步核心还会在取得执行锁后复核快照。客户端不能自行构造“已确认”布尔值来绕过摘要校验。

发布预览按文件给出 before/after，仅包含 profile.json、允许的 settings 和显式 patch 文件。Git HEAD、origin、实际 push URL、upstream 与文件差异均进入摘要。确认后只提交这些路径，并推送到已确认的实际 push URL 及 origin 上游分支；远端后来推进会由普通 push 拒绝。

## 状态转换与错误

新插件调用 install；已存在同来源的插件调用显式 update。npm --version 与 Git --ref 使用清单精确目标，应用后重新读取并比较来源、版本及启用状态。来源或子目录切换、自身操作、registry 版本变化时均在预览阻止。缺失且目标禁用的普通插件加入 skipped（plugin、reason=missing-disabled），不产生变更，跳过其设置及补丁验证；已安装的禁用插件仍按固定版本管理。恢复曾安装但已丢失的禁用插件仍拒绝自动重装，避免安装时运行代码。

Git 源码的 HEAD、状态摘要也进入预览校验，未记录修改会阻止同步。

Cafe 使用独立适配器，合并 autoUpdateOptOuts，写入前停止插件并比较原始字节。允许同步的列表之外的设置保持不变。与其他软件并发修改时拒绝，不承诺对外部进程提供跨进程原子事务。

Git 工作区不干净、上游缺失、历史分叉、无凭据、命令超时、版本不符、摘要过期、设置并发写入、未知补丁文件或中断均报告失败并保留现场。普通失败提供备份；中断后没有最终快照时不允许盲目恢复。外部安装/更新可能已产生副作用，不能把错误等同于“未发生修改”。
