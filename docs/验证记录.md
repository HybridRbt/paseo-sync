## 兼容性与边界

真实 Windows daemon、Windows 客户端与第二台 Mac 尚未逐机接入验证；CI 的平台测试不能替代这些验证。插件本身没有后台自动跨主机广播，每台 daemon 需分别安装并指向自己的配置 checkout。

GitHub、Linear 等插件的登录认证不由配置一致性验证保证。registry 版本切换、来源迁移和自身更新需要独立处理。未记录的 npm 源码手工修改不属于通用源码备份范围，应显式记录补丁；Git 源码修改会阻止同步。

开发依赖来自官方 0.11.4 scaffold，npm 报告的上游开发依赖漏洞没有通过强制升级宿主 SDK/React Native 处理。插件没有需要下载安装的第三方运行时依赖。

开发期间系统 Homebrew Node 曾因动态库更新暂不可用，使用 Codex 自带 Node 24.19.0 完成本地验证，没有修改系统 Node 或动态库。最低 Node 22.18 的覆盖见公开 CI。

## Windows 首次安装 trampoline 的 CLI 解析（GitHub #26 / THEJ-28）

自 Paseo 桌面首次引导（上游 #8363，2026-11-03）起，全新 Windows 安装会把 `%USERPROFILE%\.local\bin\paseo.cmd` 写成只含 `set "BUNDLED_CLI=<安装目录>\resources\bin\paseo.cmd"` 与 `call "%BUNDLED_CLI%"` 的转发脚本并加入 PATH。旧解析按 shim 自身位置推导桌面布局失败，npm 布局也不适用，于是按 PR #1 的兜底报 "Unsupported Windows Paseo shim"。

- 修复：按官方 trampoline 的确切形态读取并提取内置目标（绝不执行该 .cmd），目标再走与直连 bundled shim 完全相同的桌面布局校验（Paseo.exe 与 node-entrypoint-runner.js 存在）后经 `windowsLaunch` 启动；目标缺失时给出“重装桌面版或设置插件 CLI 路径”的明确提示；自定义/未知 shim 行为不变。`locate()` 的 Windows 兜底候选同步加入 `~/.local/bin/paseo.cmd`。
- 回归：新增 `trampolineTarget` 纯解析测试（全平台，含 BOM/CRLF、含空格路径、UNC、拒绝相对路径、`%VAR%` 与引号注入）与两个 Windows 专项解析测试（有效 trampoline 解析到 bundled 桌面布局、目标缺失时报可操作提示）；旧代码上先行验证为 RED（缺少导出直接失败），修复后 GREEN。旧“自定义 shim 报指引”测试保持不变并通过。
- 本机（macOS）实测 `node --test --test-concurrency=1 tests/*.test.mjs` **177 项：174 通过 / 0 失败 / 3 项 Windows 专项跳过**，`npm run typecheck` 与 `npm pack --dry-run --ignore-scripts` 通过；Windows 专项由 CI windows-latest × Node 22.18/24 执行。
- 限制：本机无真实 Windows 现场与真实 Paseo.exe，端到端“进入拉取流程”需在 Jered 的 Windows 机器复核；trampoline 解析基于上游当前 install.ts 生成的字节形态，若上游改变生成格式将回落到原有指引提示。

## Registry 插件跨版本一键重装对齐的真机实测（PR #25 后续验证）

真机 macOS、daemon 0.15.3、paseo-sync b0ccafb（含 PR #25）。牺牲性插件 `@gpambrozio/paseo-skills`（本机未安装、profile 中为禁用、npm 历史版本 0.1.2–0.4.0 共 6 个）；漂移用临时 profile 克隆制造（skills 改为启用并固定版本，删除 terracotta-themes 条目避免附带安装），真实 profile 仓库全程未改动；全程经 `tools/paseo-profile.mjs plan/apply/restore` CLI 完成。此前 0.11.4 时代实测的是 `update --version` 升降级且明确「没有卸载重装」，本节补上卸载重装语义。

- **daemon 接受 install 指定历史版本**：latest 为 0.4.0 时 `paseo plugin install npm:@gpambrozio/paseo-skills@0.3.0` 真实安装 0.3.0（返回与 `plugin ls` 的 currentRevision 均确认），不是回落到 latest。registry 源（owner/slug）install 只装 latest，指定历史版本必须走 `npm:pkg@version` 形式——这正是 reinstall 路径的实现方式。
- **remove 确实删除 plugin-settings**：卸载后 `~/.paseo/plugin-settings/skills/` 连同预先放入的 marker 文件一并消失（代码注释假设在 0.15.3 成立）。skills 插件本身不写 host 设置，「重装重建默认值」无观测对象；host-only 文档的捕获→删除→重写链路已由 marker 全程验证。
- **三态 plan（真实 registry 漂移：registry 源装 0.4.0 vs profile 固定 0.3.0）**：默认返回 conflicts「Exact registry version transition is not supported: skills. …」；`--prefer-profile` 返回 skipped `{reason: registry-version-transition, head: 0.4.0, revision: 0.3.0}`；再加 `--reinstall-registry` 返回 changes `[skills: reinstall 0.4.0→0.3.0]`。客户端按钮只在这三态间切换，其渲染与 canConfirm 已有单测，未做 UI 人工走查（经确认降级为非硬验收）。
- **apply 卸载重装对齐**：`--approve` 后按 remove→install@0.3.0→核验执行，verification 的 configurationMatches 与 runtimeHealthy 均为 true；marker 按捕获内容精确重写；备份成功后 `hostOnlySettings` 捕获条目按设计清除（sync.mjs 的 post-rewrite drop）。
- **备份恢复经卸载重装回滚版本**：restore 预览披露 skills 0.3.0→0.4.0 回滚与「Restore may reinstall previous pinned versions using the network」警示；`--approve` 执行后 skills 回到 0.4.0，marker 保留。
- **实测后真机完全复原**：skills 移除、plugin-settings 与 plugins 目录恢复初始、真实 profile 仓库无改动；drill 使用的临时 profile 状态目录（含备份，位于独立的 profiles/7de1f0fc… 下，与真实 profile 的 2fcc2916… 隔离）已删除，真实 baseline 未被触碰。

发现与边界：用 `npm:` 源直接安装不产生 registry 溯源（SOURCE 列显示 `npm:…` 而非 `plugins.paseo.sh/…`），plan 会按普通 update 处理而非 registry transition——真实漂移场景需从 registry 源安装才会触发；reinstall 对齐后安装来源显示为 `npm:` 源（daemon 不再提供 registry 块），同步比对经 descriptor 归一化不受影响。单机闭环已证实；第二台 Mac mini 的跨机同步仍待逐机接入验证。
